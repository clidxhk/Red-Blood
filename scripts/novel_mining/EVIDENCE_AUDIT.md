日期：2026-10-21。对象：`973625b` 引入的采集实现，以及随后 `16da590`、`8445ab5` 的转化工作。此次为工具与流程维护，没有重写正式设定。

## 已证实的问题

旧 `extractor.py` 将章节序号映射到预写事实列表，既未读取章节正文，也未根据正文定位证据。名称位置使用 `start_char + item_idx * 50`；陈述证据是“某物之某属性记载”这一占位文本；实体直接标记为 `verified`。这些字段不能证明陈述来自原文。

旧 `evaluator.py` 依据名称查固定映射，未实际检索本书正文或验证世界规则；旧报告却固定宣称“10/10提取完成”，并将预设转化意见写成已有充分依据的结论。报告还跨来源读取全部实体与候选，存在混书风险。

2026-10-21 对当前本地 `mushenji_v1` 数据库实跑的结果：

| 项目 | 结果 |
| --- | --- |
| 已登记章节 | 1834；仅表示切章登记，非提取覆盖率 |
| 历史素材报告中的实体数 | 23；不是已核实实体数 |
| 数据库陈述 | 41 |
| 缺少合格证据位置的陈述 | 41 |
| 新协议下的章节导入记录 | 0 |
| 本轮满足证据与语义复核条件的候选 | 0 |

位置不合格不等于这 41 条内容全是错误，更不等于所有转化稿均须删除。结论是：历史“已验证”不足采信，须回到原文逐项补证。审计详细结果仅保存在本地工作数据目录，未将小说长摘录加入 Git。
