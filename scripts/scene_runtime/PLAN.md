# 场景运行层实施计划

本文在现有八人、四阶段创作管线上增加可追溯的场景数据和输入组装工具。完成状态以代码、测试和审校结果为准。

## 目标与范围

本轮交付职责修复、数据协议、离线工具、回放样例与验证用例。正式设定正文、人物 JSON 和茶馆时间线不在本轮修改范围内。

参考 SillyTavern 的世界书、角色卡、作者注和检查点机制，沿用现有检索、撰写、预演与审校职责。工具不连接模型、不生成对白、不自动回填正式设定；模型选择、并发数与代理深度保持当前配置。

## 当前基准

- 根 `AGENTS.md` 确立八人四阶段管线，`style-writer` 为唯一正文撰写引擎。
- `character-actor` 已有逐人卡、信息边界表、临时状态和轮次场控；本轮补可验证的数据与组装工具。
- 人物底谱已有稳定事实、声线和经历；本轮不批量迁移格式或补造对白。
- 茶馆时间线已有逐回连续性记录，继续作为正式回目的依据。
- 原交叉引用脚本检查双链外的裸词，本轮增加指定范围内的双链目标核验。

## 阶段 0：统一职责与规则入口

1. 茶馆流程固定为：检索依据表 → 茶馆专项增补 → 按需人物预演 → 写手独立成文 → 多维审校。
2. `teahouse-chronicler` 读取现行茶馆 `AGENTS.md`，仅做阶段一增补；不再引用已失效的写作说明。
3. 四个阶段三审校代理只出报告，修正由主架构师落实。
4. 统一实际调度接口说明；逐人发言需不继承全知历史，工具是否提供关闭能力以当前环境为准。

验收：八份 TOML 可解析，职责与根规则一致；没有正式内容或模型配置变更。

协议分开表达来源、开场快照、世界事实、人物信念、披露许可、候选事件与正式采纳。详见同目录 README。

### 设定来源

依据表由真人或研究代理确认后选择材料，记录路径、行段、文件原始字节哈希及适用时间范围。首版显式策划选材，不实现自动语义检索。

导演包和写手包自动附根目录及目标文件沿途的 `AGENTS.md` 全文。核心法理与神族起源所需额外规范按根规则显式加入来源；工具不会从文字自动推断全部必读规范。

预算按实际输出字符计数，不能称为 token 数。必需材料超预算时失败，不截断规则或静默丢弃来源。源文或行段失效时停止组装，重新确认。

### 接收者边界

| 接收者 | 输入范围 |
| --- | --- |
| director | 全量策划材料、来源、隐藏信息与分支记录 |
| actor | 本人获准的 persona、状态、信念、言谈分寸及可见事件 |
| writer | 适用规范与显式允许向写手提供的来源、信息和预演结果 |

人物包不附完整人物 JSON、别人的私密卡、人物未知的导演信息、隐藏来源目录或分支元数据。演员已知但不能说的信息单独记录言谈分寸，不与知情许可共用一个标记。

工具筛选输入，不能禁止同仓代理自行读取其他文件。实际人物调度由主架构师根据可用能力分批直接发起，使用 `fork_turns="none"`，仅交付人物包；只在同一上下文分饰多角时必须如实标注，不能称已实现独立隔离。

### 分支与采纳

开场快照不随候选轮次修改。候选发言、动作及状态变化只写入候选事件，不直接改事实、人物状态或底谱。

创建分支时保留开场快照与已审定的基础事件，清除候选事件，记录父分支和基础事件 ID。新分支的候选不能流入兄弟分支；工具不推断或自动执行状态变化。

采纳事件须有最终正式正文来源及适用审校通过记录。校验器只能核查这些记录的结构，不能替代真实 subagent 审校，也不能自行证明审校已经发生。

正式成文和审校通过后，由主架构师按既有流程回填时间线；涉及长期人物变化时同步维护 MD 与 JSON。运行包本身不获得改写正式设定的权力。

## 阶段 2：回放与反例验证

本轮选取已完成回目的真实材料制作离线夹具，验证来源核验、输入组装和分支处理。不改写回目，不生成新演出，不把当前人物底谱的全部经历加载到早期场景。

夹具保留来源文件、行段、哈希与时点说明；测试数据中的虚构标记只用于技术验证，不成为设定。

重点验收：

- 演员包不泄露导演秘密、他人状态、隐藏来源元数据或未来事件。
- 人物误判不自动写入事实表，个人知情不等于允许公开。
- 来源缺失、哈希变化、错误行段、跨时间轴与未来来源均失败。
- 必载材料超预算失败，输出失败不遗留可误用的半成品。
- 非本分支事件、无最终依据或缺适用审校的采纳记录失败。
- 分支从同一开场依据出发，清除候选而不重复执行状态变化。
- 读取与输出不越界，不覆盖来源或正式内容。
- 双链错名、死链与同名歧义可在指定范围内检出；运行目录不进入目标与扫描集。

程序通过只证明已实现的结构条件成立。时代范围、人物分寸、信息传播和文学质量仍需人工及真实 subagent 判断。

## 阶段 3：后续真实创作试用

本轮完成后，再选择一个范围明确的新回目，依完整管线试用。记录越界发言、状态漂移、加载体积、人工修正与检索重复情况。

对白样例从审定正文提取并附出处；是否纳入稳定底谱另行判断。试用后再决定自动检索、状态重建、摘要或 SillyTavern 导出是否值得扩展。

此阶段尚未实施，不能把离线回放等同于新回目试用完成。

## 阶段 4：场景策划入口

已新增根目录 `场景/`，把“某一次具体场面如何准备”从正式设定与运行清单之间单列出来。该层保存场景卡、模板和回放示例，记录时点、地点入口、人物槽位、戏剧问题、披露边界、连续性回填项与依据缺口；长期地点正文、人物底谱、时间线和正式正文继续留在原目录。

`场景/` 被排除在正式双链目标集合与运行工具的正式正文来源之外，因此策划卡不会被误认成世界条目或 `accepted.final_source`。单张卡仍可做双链目标检查。首批只提供一张已审定第一回的回放卡，不新增剧情，也不代表真实新回目试用已经开始。
