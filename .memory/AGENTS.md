# 持久化记忆规范

本规范仅适用于 `MEMORY.md` 与 `.memory/` 内的长期协作记忆。仓库正文、目录结构、双链关系和单轮任务状态以项目文件与 Git 历史为准，不得复制进记忆系统。执行新增、修改、检索或删除记忆前，必须先阅读本文件；根目录 `MEMORY.md` 只作索引，不承载详细正文。

## 一、适用时机

1. 用户明确要求记住、更新或遗忘某项长期信息时，立即按本规范处理。
2. 用户给出稳定的创作偏好、反复适用的工作反馈、仓库无法直接推导的项目背景或外部资料入口时，可主动沉淀。
3. 用户要求回忆、查阅或应用记忆时必须检索；用户要求忽略或禁用记忆时，视同 `MEMORY.md` 为空。
4. 依据记忆提出正式创作建议前，必须核验其中涉及的路径、专名、人物、势力和纪年是否仍与仓库现状一致。

## 二、四种记忆类型

### `user`

记录用户的创作者定位、长远目标、题材倾向、表达习惯、擅长领域与希望获得补位的方向。只收录与长期创作协同直接相关的事实，不作主观负面评判。

### `feedback`

记录用户对工作方式的稳定纠正或明确肯定，包括应持续规避的禁忌和已经验证有效的范式。正文依次写明核心准则、**原因：**、**应用场景：**，以便在边界情境中正确裁量。

### `project`

记录仓库正文无法稳定推导的工程目标、阶段节点、优先级、交稿日期、设定债务和剧情主线。相对日期必须换算为绝对日期；正文依次写明事实或结论、**原因：**、**应用场景：**，并及时更新失效状态。

### `reference`

记录外部资料入口、素材库、设定底稿、角色卡源文件或其他需要跨会话定位的参考资源及其用途。只记录入口和使用条件，不复制可随时读取的大段内容。

## 三、严禁存入记忆

- 仓库内已经明确记载的设定正文、文件路径、目录层级和双链关系。
- 单次任务的即时改稿过程、临场措辞、一次性灵感和进行中状态。
- 可直接从现有文档或 Git 历史查证的标题、正文、命名演变与版本差异。
- 临时场景、试演事件、候选分支、运行包、自动摘要和未采纳草稿。
- 敏感信息、凭据，以及用户没有要求长期保存的私人资料。

即使用户要求保存上述内容，也只提炼其中确有长期价值、且无法从仓库稳定查证的规则或背景；不能把记忆系统变成正文副本、任务日志或进度档案。

## 四、文件结构与索引

每条记忆写入 `.memory/` 对应主题子目录中的独立 Markdown 文件，使用以下头部：

```markdown
---
name: {{记忆名称}}
description: {{用于判断相关性的单行描述}}
type: {{user/feedback/project/reference}}
---

{{记忆正文}}
```

同时在根目录 `MEMORY.md` 的对应主题下维护单行索引：

```markdown
- [标题](文件相对路径) — 单行功能摘要
```

索引每条控制在 150 字符以内。新建前必须检索能否并入现有记忆；文件改名、移动、合并或删除时同步维护索引，严禁留下重复条目和失效链接。

## 五、检索与核实

1. 先读 `MEMORY.md`，只打开与当前任务相关的记忆正文，不批量灌入全部历史。
2. 记忆中的特定路径须先确认仍然存在；专名、人物、势力、法理和纪年须在仓库中检索当前用字与最新状态。
3. “记忆中曾有记载”不等于“仓库当前仍以此为准”。正式设定正文、人物 JSON、时间线和最新审定条目优先于旧记忆。
4. 发现记忆过期时，更新或删除记忆及其索引；不得为了维护旧记忆而反向修改正式设定。

## 六、与其他机制的分工

- 规划用于对齐整体改写路径和扩写时序。
- 任务用于追踪当前一轮的检索、执笔、审校和回填。
- Git 记录文件变更与历史版本。
- 记忆只沉淀长期稳定的用户偏好、工作反馈、仓库外项目背景和参考入口。

所有记忆文件修改仍遵守根目录 `AGENTS.md` 的精确暂存、中文提交和推送规则。
