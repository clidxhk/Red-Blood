name: workflow-git
description: 每轮修改完成后立即 git commit 落库并汇报哈希；并行会话环境下只精确暂存本任务文件，禁用 git add -A，防中文路径 diff 假阴性
type: feedback
---

规则一：每一轮修改（新建设定、扩写、重构、回填旧文）完成后，必须立即 `git add <改动文件>` 并 `git commit`，把修改真正落进提交历史，然后向用户汇报提交哈希与改动文件数；不把"已暂存"说成"已缓存"。

规则二：提交本任务改动时，只逐个 `git add -- <本次任务实际改动的文件>`，禁用 `git add -A` / `git add .` / `git commit -a`。若开工时工作区快照 clean、收尾时却出现大量陌生改动，说明有并行会话在改同一工作区——此时只提交自己动的文件，把别人的改动留在工作区，并在汇报中说明。

规则三：同一文件可能被自己与并行会话混合修改（如某次 起源总纲.md 既有本任务的回填，也有对方的新增论述）。这种情况下不能整文件提交，应先看 `git diff` 分清改动归属；若自己的改动与对方改动无法在文件内分离，宁可暂不提交该文件或先与用户确认，也不能把他人未完成的工作一并落库。

规则四：Windows + Git Bash 下用 `git diff --quiet -- "中文路径.md"` 判断文件是否干净会假阴性（中文参数经 shell 编码转换后与 git 内部路径不一致，已改动文件被误判为 CLEAN）。判断干净与否改用 `git status --porcelain -z` 或 Python `subprocess.run([...])` 直接传参，不依赖 shell 内联的中文路径字符串。

**原因：** 用户多次发现此前只执行了 `git add` 暂存而未 commit，误以为内容已落库，造成重复确认与不信任，明确要求"以后每一次修改都需要缓存在Git里"；本仓库实际发生过多会话并行编辑，git add -A 曾差点把并行会话的半成品一并提交；中文路径 diff 假阴性则曾险些误判 9.农神.md 为干净。

**应用场景：** 本仓库所有任务的收尾落库环节：先 `git status --short` 与 `git diff --stat` 核对改动范围，逐个文件显式 add，commit 后汇报哈希；对出现非预期改动的文件，先 diff 确认归属再决定。
