# 场景策划层

`场景/` 保存“某一次具体场面如何准备”的策划卡，不保存人物底谱、世界地点正文、正式时间线或审定故事。它是创作管线的中间层：向上承接世界与人物事实，向下生成导演、写手和人物发言者的输入包。

## 五层分工

| 层 | 主要入口 | 负责回答 | 不负责 |
| --- | --- | --- | --- |
| 人物层 | `角色/` | 这个人是谁，稳定性格、关系、能力与经历如何 | 这一场临时知道什么、想做什么 |
| 世界层 | `世界/` | 哪些法理、地点、势力、器物长期成立 | 某场戏怎样开局和收束 |
| 场景层 | `场景/` | 这一次何时、何地、何人因何入场，冲突怎样推进 | 替代正式设定、故事正文或连续性记录 |
| 连续性层 | `故事/` 中的时间线、审定正文与系列说明 | 已经发生了什么，下一章必须接住什么 | 尚未采纳的试演方案 |
| 组装层 | `scripts/scene_runtime/` 与 `.workbench/runs/` | 如何核验来源、裁剪权限并生成三类输入包 | 自动判断文学质量、人物动机或事实真伪 |

`故事/茶馆闲聊/场景/` 中现有的 [[偏街旧茶馆]]、[[回青医馆]]、[[保和丹铺]]属于**场所正文**，说明这些地方长期是什么样。根目录 `场景/` 则记录**具体场次任务**，说明这一次在这些地方发生什么。两类文件不互相替代。

## 场景卡应装什么

一张卡只对应一个可执行的场次，至少写清以下内容：

- 目标篇章、时间轴节点、回目或章节的承接位置。
- 地点入口、时令天候、空间限制、声音气味与灵机等感官锚点。
- 人物槽位：为何在场、本场目标、开场状态、知道什么、能说什么、何时离场。
- 戏剧问题、开场触发、冲突线、节拍、必须透露、可暗示与禁止透露。
- 场外压力、物件位置、伤势、费用、巡禁、传讯等会影响判断的临时条件。
- 退场后的连续性变化，以及需要回填时间线、人物 MD/JSON 或世界正文的触发项。
- 已核验的来源路径与适用范围；需要精确组包时，再把这些来源写入 `scene_runtime` 清单。

人物槽位只提炼本时点成立的材料。完整人物卡留在 `角色/`；场景卡不复制稳定设定，也不以临时目标覆盖长期动机。

## 场景卡不应装什么

- 整篇人物正文或完整 JSON 底谱。
- 整章地点志、势力总纲或历史叙述。
- 已审定正文的改写稿；草稿和生成包放在 `.workbench/`。
- 尚未采纳的试演对白被直接写成世界事实。
- 自动摘要、模型推测或无出处的“应该有”。
- 一张卡包办多章、多个平行时点或多个互相排斥的分支。

## 文件与状态

按系列和具体场次归档，每场把策划与运行清单放在一起：

```text
场景/
├── README.md
├── AGENTS.md
├── 模板/
│   ├── 单场景策划模板.md
│   └── 茶馆夜话策划模板.md
└── 茶馆闲聊/
    └── 第一回开场/
        ├── 策划.md
        └── scene.json
```

其他系列使用相同目录形式，例如 `场景/炎帝崛起/<卷章与场面短题>/`，有实际任务时再创建。
`策划.md` 记录目的、视点、冲突、节拍与收束；`scene.json` 记录经过核验的来源、时点、人物状态和逐人披露。v1 不支持的创作字段留在策划中，工具不会自动读取或转换策划。来源路径从仓库根目录起算，不从场次目录起算。候选分支和生成包仍留在 `.workbench/runs/`。

场景卡状态统一使用以下五种：

| 状态 | 含义 |
| --- | --- |
| `策划中` | 仍在查证、选材与补缺口 |
| `待预演` | 依据表与人物边界已足以试演 |
| `待成文` | 已选定互动草稿，等待写手正式撰写 |
| `已审校` | 正式正文和适用审校均已通过 |
| `已回填` | 时间线及必要的人物或世界条目已同步更新 |

状态只说明流程位置。`已审校`之前的内容都不是正式事实，生成包和试演分支也不因保留在文件里而自动获得采纳资格。

## 使用顺序

1. 先由检索阶段形成依据表，核查时间线、地点、人物在位与认知边界。
2. 复制[单场景模板](模板/单场景策划模板.md)；茶馆任务另用[茶馆夜话模板](模板/茶馆夜话策划模板.md)，按系列建立本场目录。
3. 审核卡内来源与信息边界，再据卡生成 `scripts/scene_runtime/` 所需清单。
4. 需要多人物交锋时，交给 `character-actor` 预演；试演事件只记为候选。
5. 由 `style-writer` 依类别规范独立成文，再走语气、交叉引用、人物与必要的跨文件一致性审校。
6. 正文正式采纳后，回填系列时间线和长期变化，最后把卡标为 `已回填`。

## 当前入口

- [场景层规范](AGENTS.md)：写作边界、来源要求、状态和校验口径。
- [单场景模板](模板/单场景策划模板.md)：时空、视点、诉求、信息边界与可伸缩节拍。
- [茶馆夜话模板](模板/茶馆夜话策划模板.md)：熟客与过路客、在位核对、八部分结构与席间节奏。
- [回放示例](茶馆闲聊/第一回开场/策划.md)：从已审定正文提取的技术回放卡，不产生新剧情；配套 [scene.json](茶馆闲聊/第一回开场/scene.json) 与策划同目录。
- [场景运行协议](../scripts/scene_runtime/README.md)：来源哈希、逐人披露、预算和分支规则。
- [世界约束索引](../scripts/world_constraints/README.md)：人工查证辅助，不能替代正式原文。

场景卡受双链目标检查保护，但本身不进入正式双链目标集合。可对单张卡执行 `python scripts/check_crossrefs.py --check-links "场景/具体卡.md"`，检查其引用是否指向真实且唯一的正式文件。
