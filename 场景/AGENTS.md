# 场景策划规范（场景目录）

普通场景可在任务依据表中完成轻量策划，不强制另建卡或目录。长期复用时可归档为 `场景/<系列>/<场次>/策划.md`；复杂信息隔离、多分支或可重放任务才配套 `scene.json`。启用运行清单后须完整遵守 v1 校验契约，来源路径从仓库根目录起算。

本规范适用于 `场景/` 下的全部策划卡、模板与回放示例。根目录 `AGENTS.md` 的四阶段创作管线、交叉引用原则和审校纪律仍然有效；本文件只界定场景层的职责、证据要求与归档边界。

## 一、文件性质

1. `场景/` 是正式正文之前的策划层，不保存世界观定论、人物稳定底谱或正式连续性。
2. 每张卡只规划一个具体场次、一个主时间点及可明确执行的分支。跨章总纲放回 `故事/`，地点长期设定留在原类别目录，人物稳定资料留在 `角色/`。
3. 策划卡中的目标、冲突、节拍和候选反应可以调整；正式正文、时间线与 MD/JSON 只能按既有审校和回填流程更新。
4. 策划卡不得充当 `scene_runtime` 的正式 `target_paths` 或 `accepted.final_source`。校验器会把顶层 `场景/` 排除在正式 Markdown 来源之外。
5. 尚未采纳的完整草稿、角色包、分支清单与生成文本写入 `.workbench/`，不以场景卡名义混入正式内容。

## 二、与既有“场景”目录的区别

`故事/茶馆闲聊/场景/` 保存的是茶馆附近的场所正文，回答“这个地方长期是什么样”。根目录 `场景/` 保存的是场次策划，回答“这一次在这里发生什么”。不得把既有场所正文整篇复制进场景卡，也不得因新增策划卡而搬动该目录。

## 三、轻量策划与可选扩展

普通场景写清本场必要性与承接、人物目标、关键选择及代价、结尾相较开场的变化、视点与披露、必要来源和回填项即可；没有相关变化的项目可省略或简记理由。静场与过渡可改变读者理解或情绪，不强求争斗、反转与重大选择。

完整模板是可选扩展。时令感官、人物槽位、场外压力、节拍、物件位置、逐项信息边界等，按实际难点增补，不要求每格必填或另建一套表。百科式设定条目不套场景验收。

只有复杂信息隔离、多分支或可重放需求才启用运行清单、哈希与输入包。启用后须记录目标、时点、来源与逐人授权等全部必填数据，不削弱严格校验；无直接依据的推演始终单列。

## 四、写作与信息边界

1. 稳定事实查 `世界/`、`角色/` 与审定正文；当前连续性查 `故事/` 中对应系列的时间线。
2. 场景只摘取本时点成立的人物经历、境界、关系与认知。不得把人物后来知道的事、后来获得的伤势或身份提前加载。
3. “在场”不等于“知情”，“知情”不等于“可以说出”。作者/写手真相、人物知情与信念、读者本段获知范围分别判断。写手为伏笔、潜台词与反讽掌握必要真相时注明呈现方式；这不等于让人物知晓或向读者全部说破。运行工具仍以 `disclose_to` 授权写手，不新增读者字段，人物未知秘密不得交演员。
4. 场景卡可以提示人物语态与冲突方向，不得代写整段最终对白，也不得让所有人物替作者解释设定。
5. 茶馆条目必须另经 `teahouse-chronicler` 增补时间线、在位状态、八段节拍和席间基调；场景卡不替代该步骤。
6. 主架构师用一句话简记创作难题与是否启用预演；仅因用户要求，或复杂知情差、重大选择动机、多人博弈、对白失真等难题才考虑调用 `character-actor`，不按人数或重要对白自动触发。启用后只试必要片段或对照方案，问题解决或无新价值即停止，交写手自由剪裁；候选发言不自动成为事实。

## 五、引用与校验

1. 卡内引用正式文件时，使用与实际文件名逐字一致的 `[[文件名]]`；不得引用另一张场景卡冒充正式依据。
2. 场景卡本身不进入全库正式双链目标集合，避免策划标题被当成世界观条目。
3. 对单张卡运行 `python scripts/check_crossrefs.py --check-links <路径>`，确认引用均指向真实且唯一的正式文件。
4. 需要组装输入包时，按 `scripts/scene_runtime/README.md` 记录来源路径、行段、整文件 SHA-256、时间范围和逐人披露。
5. 来源文件变化后，重新阅读并核对摘录，再决定是否更新清单；不得仅为消除哈希错误而盲目重算。

## 六、状态与验收

场景卡状态只能取 `策划中`、`待预演`、`待成文`、`已审校`、`已回填`。

- `待预演` 仅在已决定启用预演时使用；进入前须明确具体难题、目标、时点、人物边界和必要来源。未启用者可直接进入 `待成文`。
- 进入 `待成文` 前：本场变化、视点与披露、必要来源须明确；有分支时确认所选分支，已预演时交付可取舍材料，不要求先有互动草稿。
- 进入 `已审校` 前：正式正文已通过对应类别的全部适用审校。
- 进入 `已回填` 前：系列时间线及长期人物、物件或世界变化已按实际影响同步更新。

程序校验只能证明结构、来源和披露配置成立。文学验收另看场景必要性、选择与代价的因果、人物或读者理解的变化及继续阅读动力；工具通过不能证明人物真实、场次好看或质量提升。
